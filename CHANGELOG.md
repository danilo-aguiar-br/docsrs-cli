# Changelog
All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).


## [1.3.0] — unreleased

### Fixed
- **Both published runbooks taught a wire field that no longer exists, and left the designation rule unwritten (GAP-SKILL-CONTRACT-001):** `skills/*/SKILL.md` told agents to read `config init` data as `source`, which the ETD work in this same release renamed to `target_source`; an agent following the runbook reads an absent field and cannot tell which layer chose the path. `cache clear` gained the same field and neither runbook listed it. Worse, the two verbs that now refuse an ambient target had no rule written anywhere in either file: the formulas passed `--yes` and no line explained that omitting both the waiver and the target flag exits 64, so a reader who typed `cache clear --json` met a refusal the runbook could not resolve. Four further claims were refuted by execution: `planned_params` was said to always carry the canonical `crate_name`, which is false for `search-crates` (`q`, `per_page`, `sort`, `page`); `planned_method_anchors` existed in every method and variant plan and was named nowhere; `validation`, `planned_parent_kind` and `parent_kind_probe` were cited without saying they live *inside* `planned_params`; and `config show` was documented as always emitting `lang`, `log_directive` and `contact`, which are omitted until set. The canonical `error.kind` list also omitted `io`, the kind this release added. Both files now carry an `Explicit Target Designation` section, corrected field lists, the two extra `--online` doctor checks, and the `cache path` `source` versus `cache clear` `target_source` distinction that a sibling-name drift makes easy to miss.
- **Both runbooks exceeded the four-thousand-word ceiling they are written against (GAP-SKILL-BUDGET-001):** the English file measured 4494 words and the Portuguese 4635, and the corrections above only add. Redundant bullets were merged rather than capabilities dropped, near-identical formulas collapsed onto one line naming every accepted value, and the files now measure 3830 and 3891 words at identical line counts. Every token the derived gates demand survives: the eight reduction flags, all twenty-six invocable command paths from `wire_name`, and all thirteen wire kinds.

### Changed
- **`Cargo.toml` carried a denylist beside its allowlist (GAP-PKG-ALLOWLIST-002):** an external packaging helper merged sixty-nine `exclude` patterns into a manifest whose `include` had deliberately replaced them, and reported `effective=0` in the same breath — Cargo discards `exclude` outright when `include` is present. Sixty-nine dead lines reading as protection is the exact shape the allowlist migration removed. The array is gone again, and `the_manifest_uses_an_allowlist_and_not_a_denylist` in `tests/policy/packaging.rs` is what caught it.

### Security
- **`config init --force` overwrote a target the caller never named (GAP-ETD-CONFIG-001):** the approved plan that taught `cache clear` Explicit Target Designation said this verb would learn it too, and gave the reason in as many words — it overwrites a file. Only the sibling was built. `ConfigAction::Init` carried `force: bool` and nothing else, so `--force` knocked out the single guard-rail (`ConfigAlreadyExists`, exit 78) without ever requiring that the directory be named. The audit that found this destroyed the maintainer's own `config.toml` in the act of measuring it: exit 0, no backup, no waiver, and no field recording which layer chose the path. `--force` now demands `--config-dir` naming the directory or `--yes` accepting the XDG one, and refuses with exit 64 otherwise — including where no file exists yet, because a caller cannot know that about a directory they never named, and a rule answering from the state of the disk gives one argv two behaviours. `ErrorDetail::AmbientTargetRefused` gained `effect`: its message said "would delete" for every caller, which was simply false the moment a verb that overwrites started using it. `ConfigInitResult.source` is now `target_source`, matching `cache-clear` — two names for one concept across two destructive verbs is the drift this repository keeps finding. Without `--force` nothing changed: demanding ceremony where there is no victim teaches callers that the waiver is noise.
- **The designation rule lived inside a `match` arm, where nothing could ask it a question (GAP-ETD-CLASS-001):** `tests/policy/*.rs` contained no occurrence of `destructive`, `ambient` or `waiver`, and the four ETD tests spoke only of `cache clear`. The approved plan called for a class gate over every destructive verb; it was never built, and `config init --force` is the proof of what that costs — a second destructive verb shipped without a waiver while every gate agreed with the tree. The rule is now data in `src/cli/destructive.rs`, read by the runtime guards *and* by seven new gates in `tests/policy/etd.rs`. The class gate walks every leaf of `Cli::command()` and fires on two signals, because each alone has a hole: prose alone misses `config init`, whose `about` promises only to create a file, and an override flag alone misses `cache clear`, which deleted with no flag at all before `--yes` existed. Proved by failing: removing `CONFIG_INIT_FORCE` from the register makes the gate name it, quote its description and list its flags.
- **`cache clear` deleted a target the caller never named (GAP-ETD-CACHE-001):** `CacheAction::Clear` carried no argv field at all, so it emptied whatever cache root the environment resolved — the confused-deputy shape, where the caller names the verb and the environment names the victim, with nothing comparing the two. The read-only sibling `cache path` already reported `source` as `cli`, `xdg` or `unresolved`, so the harmless verb disclosed which layer won and the destructive one did not; that is destructive ergonomics copied from a read verb. `cache clear` now requires either `--cache-dir` naming the root in argv or `--yes` as an explicit waiver, and without one of them it exits 64 with `kind=usage` and deletes nothing. The new `ErrorDetail::AmbientTargetRefused`, translated in both locales, names the directory that was about to be emptied, because a refusal that hides the victim teaches the caller nothing. The `cache-clear` envelope and its schema now carry `target_source`, reusing the existing `PathSource`. New suite `tests/etd_target_designation.rs` covers the ambient branch — which had never been tested — and one of its four tests asserts that `cache path` keeps inheriting the ambient root on purpose, because demanding ceremony from a read verb would be the same mistake mirrored.

### Fixed
- **Twenty-two recipes taught an invocation the product now refuses (GAP-DOC-RECIPE-001):** twelve files, including both published `skills/*/SKILL.md` runbooks, taught `docsrs-cli cache clear --json` and `docsrs-cli config init --force --json`; both exit 64 with `kind=usage` and act on nothing, and `--yes` appeared in no recipe document at all, so a reader could not discover the way out. The recipes were correct when written and became wrong the day the verbs learned Explicit Target Designation. The sibling gate added alongside this one asks whether the migration guide *announces* the break; nothing asked whether any document still *teaches* it, which is the direction a reader actually meets — nobody consults a migration guide before copying a one-line recipe. All twenty-two now pass `--yes` with `--cache-dir` / `--config-dir` named as the alternative, and `no_document_teaches_a_destructive_invocation_that_would_refuse` reads the same register the runtime reads, accepting either designation and scanning the invocation to end of line because designation may follow the verb at any position. `CLAUDE.md` is exempt with the reason stated: it is the operator's file, excluded by the `include` allowlist, and teaches no reader of this crate.
- **Three accepted item kinds appeared in no list (GAP-DOC-ITEMKIND-001):** `ItemKind::parse` accepts `variant`, `structfield` and `field`, and `src/cli/mod.rs` — whose `/// Kind:` doc comment is a hand-written pipe-separated copy of that match — named none of them, as did `README.md` and its pt-BR twin, which mirror the same string. `get-item std variant Option::Some` resolved with exit 0 while every list a caller could read said otherwise. The kind gates in this repository cover `ErrorKind`, the vocabulary a caller reads *off* the wire; nothing covered `ItemKind`, the vocabulary a caller must write *into* argv, and that is the direction where being unlisted means the feature may as well not exist. `every_accepted_item_kind_is_named_where_the_kinds_are_listed` extracts the spellings from the match itself, following the `wire_name` precedent, and found the defect on its first run.
- **Two 1.3.0 entries were filed under a July release (GAP-DOC-CHANGELOG-002):** `CHANGELOG.pt-BR.md` carried 82 items under 1.3.0 against 84 in English, and the two missing ones sat inside `## [0.1.2] - 2026-07-18` — one of them announcing `agent-surface`, which did not exist until 1.3.0. A release from July had begun claiming what shipped in August. The cross-document gate compares schema *counts* between documents and cannot see this: nothing compares entries between the two changelogs. Both items moved to the 1.3.0 `Added` section with their text unchanged, and parity is now 84 on each side.
- **The migration guide called a caller-breaking release additive (GAP-DOC-MIGRATION-002):** `docs/MIGRATION.md` opened its 1.3.0 section with the heading `additive` and the sentence "Nothing in the JSON contract was removed or renamed", and four things contradicted it. `cache clear` and `config init --force` had just learned Explicit Target Designation, so both now refuse with exit 64 and act on nothing — a 1.2.x script running either one stops working. The `config init` envelope renamed `source` to `target_source`, which is a rename in the JSON contract by any reading. `error.kind` gained `io` at exit 74 for environment I/O, where the identical failure previously arrived as `internal` at exit 70, so the exit code moved and an exhaustive `kind` matcher falls through; `retryable` also flipped to `true` for a transient cause where it had always been `false`. A reader would have concluded no action was needed and learned otherwise in production. Both guides gained a `1.3.0 breaking` section ahead of the additive one, each break paired with its way out, because naming a break without naming the escape leaves the reader unable to act. The class is closed by `the_migration_guide_names_every_verb_that_learned_to_refuse`, which reads the same register in `src/cli/destructive.rs` that the runtime reads: the sibling ETD gates cover the runtime, the schema and both configuration references, which is exactly why all of them were green — none of them reads the migration guide, and gaining a waiver is the event a migration guide exists to announce.
- **The schema index listed nineteen of twenty schemas and three of nine decisions (GAP-DOC-INDEX-001):** `docs/schemas/README.md` is the one file whose entire purpose is to be an inventory, and it was the one file no gate read. `agent-surface.schema.json` was absent from both of its language halves, and its `### Architecture decisions` section stopped at 0003 while `docs/decisions/` held nine — ADR 0005 and ADR 0009 were linked from no document and no source file anywhere in the repository, and ADR 0006 and ADR 0008 only from inside `src/`. Three existing gates read this subject and all three reported green, each correct about what it declared: one compares the *number* written in prose against the disk, and the sentence said twenty while the list beneath it held nineteen; another requires every schema name in `AGENT_DOCS`, which is the two `docs/AGENTS` files and not the index. A count is not an inventory and a sibling document is not one either. New `tests/policy/inventory.rs` derives the expectation from `docs/schemas/` and `docs/decisions/` and splits the index at its language heading, because a name present once satisfies a whole-file scan while leaving one of the two readers unable to reach the document. The `.pt-BR` twin is excluded from the expectation: it is the same record translated, not a second record. Proved by failing, with ADR 0009 deleted from the Portuguese half — the gate named the exact half.
- **A translation was quietly shorter than its original (GAP-DOC-I18N-003):** `docs/decisions/0004-threat-model.pt-BR.md` was missing `## CVSS usage` outright, which is the section stating how a reported vulnerability gets prioritised — absent from the Portuguese half of a security document. Measured across the whole tree, thirty-odd language pairs agreed exactly and one did not, so the invariant was real and simply unguarded: this product is bilingual by mandate and no gate had ever compared a pair against itself. The mirror defect was present too, `docs/MIGRATION.md` carrying `Camada Y` in two lines of an English file. `no_translation_drops_a_section_its_original_carries` now pairs by file name and compares second- and third-level heading counts; a missing twin does not fail, because `llms-full.txt` is a deliberate single-file bundle and demanding a twin for it would teach the gate that intent does not matter. Heading count is a proxy, and it is the proxy that found the real one. It still cannot see an empty section under a present heading, and that limit is recorded rather than implied.
- **The published documentation had never been compiled (GAP-DOC-LINKS-001):** `RUSTDOCFLAGS='-D warnings' cargo doc --no-deps` failed with exit 101 and 83 broken intra-doc links across 29 files, in a crate whose rule is that code carries rustdoc for docs.rs. 106 links were written bare as `` [`ErrorKind::X`] ``, a form rustdoc resolves through the module's `use` list, so tidying an import in one file silently broke the documentation of another; 29 of the 36 files had already fallen that way. The repository already had the right convention in 26 links written `` [`crate::…`] ``, which makes the bare form the deviation rather than a style choice, so all 106 became fully qualified and now resolve regardless of imports. Five more pointed at `crate::ops` and `content_type::TLS_*`, both private, which public documentation may not hyperlink at all; they became inline code, keeping the prose and dropping a promise rustdoc cannot honour. No item changed visibility, so the public surface is unchanged. The class is closed by `scripts/check-docs.sh` below.
- **The command that validated the documentation was weaker than the defect (GAP-DOC-GATE-001):** no gate in the tree ran `cargo doc` — not `check-all.sh`, not the policy suite, which reads source as *text* and cannot tell whether a doc link resolves. That is how 83 broken links survived 512 tests and 57 green gates. Worse, `CONTRIBUTING.md` taught `-D missing_docs -D rustdoc::broken_intra_doc_links`, a set that omits `rustdoc::private_intra_doc_links` — precisely the class that produced the last five failures of that run, so a maintainer following the documented command to the letter saw green while the documentation did not build. New `scripts/check-docs.sh` runs `-D warnings` instead, which is the superset, so a lint rustdoc gains tomorrow is enforced the day it ships rather than the day someone remembers to add it. `check-all.sh` discovers it by glob, so it entered the run by existing. `--cfg docsrs` is deliberately absent: `src/lib.rs` gates `feature(doc_cfg)` behind it, that feature is nightly-only, and this repository pins stable 1.88.0. The error counter uses bash pattern matching rather than `grep` or `rg`, because the policy suite left shell precisely to stop depending on tools a host may lack, and a counter needing one more binary is a counter that reports nothing where it is absent. The gate also fails when rustdoc exits 0 having emitted warnings, since that silence would mean `-D warnings` stopped being applied. Proved by failing, with an invented link injected into `src/item_kind.rs`.
- **Eight audit scratch files were published inside the crate (GAP-PKG-JUNK-001):** `cargo package --list` carried `tr.txt`, `st.txt`, `st2.txt`, `pkg.txt`, `out.json`, `out2.json`, `g.json` and `f.json`, plus `gaps.md` at 148 KiB of a 561 KiB crate. The `exclude` list in `Cargo.toml` is an inventory of known names, so it encodes the sample that produced it and never the class, and a loose file with a new name ships without anything objecting; `.cargoignore` sits in the tree looking like protection Cargo never reads. The pre-publish auditor failed for the identical reason — its own junk predicate is another list of names, and it saw `gaps.md` while missing all eight. The defect ledger left the package together with `tests/policy_gates.rs` and `tests/policy/`, because those gates derive every expectation from the working tree and answer nothing inside a tarball; shipping one without the other would leave a test that cannot pass. Verified by diffing `cargo package --list`: nineteen paths left and zero entered, the suite still runs 57 green gates against the tree, and the crate fell to 472 162 bytes. The class is closed by the allowlist migration below.
- **The gate that closed the configuration reference covered 24 of its 32 flags (GAP-GATE-GLOBAL-FLAGS-001):** `every_global_flag_appears_in_the_configuration_reference` scanned `src/cli/mod.rs` for `#[arg(… global = true …)]`, and its own rustdoc explained why that was enough: `AgentArgs` arrives by `#[command(flatten)]` and is watched by a gate in `contract.rs`. Both claims were true and they were never confronted. That sibling gate requires the eight reduction flags across fifteen `CONTRACT_DOCS`, and `docs/CONFIGURATION.md` is in none of them — it is the one document promising to teach every knob, and a quarter of its promise was unfalsifiable. Deleting the `--dedupe-by` line from it left all 43 gates green. The extraction now asks the parser: `Cli::command()` has already merged every flattened struct, so a flag declared in a file nobody thought to grep is in scope the day it is written, and no path appears in the function at all. Two arguments are exempt, `help` and `version`, and the exemption list is asserted to hold exactly two — an exemption that can grow quietly is the same hole one level up. Fourth recurrence of the class this repository hunts: the predicate encoded the sample that produced it.
- **Environmental I/O failure arrived as a defect in this binary (GAP-ERRKIND-IO-001):** a full disk writing `config.toml.docsrs-cli.tmp` produced `code 70`, `kind internal`, `retryable false` — three claims and three wrong. `internal` tells an agent to file a bug against a CLI that behaved correctly; `false` denies a retry that succeeds the moment an operator frees a block; 70 is reserved for defects in this crate. Directly above the mapping sat a comment promising a config-versus-infrastructure split that was never implemented, which is worse than no comment: it ends the investigation. New `ErrorKind::Io` reports wire `io` at exit 74, which is `EX_IOERR` in sysexits and a code the contract already declares ambiguous until `kind` is read. Retryability now comes from `IoCause`, classified where the `std::io::Error` is still in hand, because `ENOSPC` and `EACCES` share an `ErrorKind` and deserve opposite answers; an unknown cause classifies as permanent, since stopping early costs one run and retrying in vain costs every run left. `error.schema.json` gained a real `enum`, which it never had — the thirteen kinds lived only inside a `description`, so a validator could not reject a kind that only prose forbade.
- **Sixteen filesystem failures discarded the path they had just tried to open (GAP-IO-PATH-001):** `src/cache/disk/store.rs`, `src/cache/disk/maintain.rs` and `src/http/rate_limit.rs` built `ErrorDetail::Io` with `path: None` at sixteen call sites, every one of them holding the path on the stack. An operator whose disk filled learned which *operation* failed and never which *file*, which is the single actionable fact in an I/O failure. One closure, `io_at(op, path)`, now classifies the cause and keeps the path, turning eight lines of boilerplate into one at each site. Doing so pushed `src/error/detail.rs` over the 500-line ceiling, and the split was by responsibility rather than by size: `classify.rs` decides how a failure is reported, `detail.rs` remains the catalogue of what can fail, and the two grow for different reasons.
- **The bootstrap named a provider it does not install (GAP-PROVIDER-COMMENT-001):** `src/main.rs:32` read `install process CryptoProvider once (rustcrypto; …)` while line 42 called `rustls::crypto::ring::default_provider()` — residue of the reverted pure-Rust experiment, the same class as GAP-ADR-001. Three provider gates scan that file and all three reported green: one requires the shape `provider = X`, another requires `**X** (accepted)` or `X::provider()`, and a bare name inside parentheses matches neither. The aggravating detail is the location: `src/main.rs` is the file `installed_provider()` reads to decide what the truth *is*, so the source of truth contradicted itself and every gate derived from it agreed with it. New `no_line_names_a_foreign_provider_as_the_active_one` matches the bare name on a word boundary plus active voice, reusing the `canon` helper that already folded `rustcrypto` onto one spelling and had never been asked this question. `DISCLAIMS` moved to module scope so the purity gate and this one share it, ADR 0007 is exempt by path because weighing candidates by name is its job, and the gate carries a canary with the real line so a dead predicate cannot pass for a clean tree.
- **Three documents still dated the schema bundle wrong for 1.2.0 (GAP-DOC-HISTORY-001, residue):** the manual correction fixed the four documents someone remembered to open. The new agreement gate found the rest on its first run — `docs/HOW_TO_USE.md`, its pt-BR pair and `llms-full.txt` still said twenty for 1.2.0, and `llms-full.txt` still credited `agent-surface` to that release, which is the exact corruption the gap was opened for.

### Documentation
- **Three of the four schemas in each family served a contract the binary violates (GAP-SCHEMA-SIBLING-001):** `cache clear` emits `target_source`, and `cache.schema.json`, `cache-path` and `cache-stats` did not declare it; `config init` emits `target_source` and three of its four siblings still declared `source`; `config show` emits `log_directive` and only `config-show.schema.json` knew the field. All three laggards in each family were byte-for-byte identical, same sha256, which is what a frozen copy looks like. The cause was a correct fix: the dispatch had moved from one umbrella file per family to one file per wire name, and nothing then compared the four members to each other. Because `src/meta_cmds/schema.rs` embeds these with `include_str!`, the CLI itself handed agents a document that rejects the CLI's own output — and with `additionalProperties: false` the cost is asymmetric: no data goes missing, correct data gets refused, which destroys trust in the reply that was right. New `no_schema_drifts_from_the_siblings_that_share_its_shape` groups schemas by the set of `oneOf` variant titles they declare and demands identical bodies inside a group. Nothing lists which files are siblings; the files say so themselves.
- **Five schemas rejected the CLI's own valid output (GAP-SCHEMA-REJECT-001):** `schema.schema.json` required `command` and `schema` while `--cmd all` emits `mode`, `commands` and `items`, so the twenty-name bundle the index recommends failed the schema of the command that produced it. `dry-run.schema.json` fixed `additionalProperties: false` without declaring `agent_surface`, so every dry-run combined with any reduction knob failed validation. `version.schema.json` left `os` and `arch` optional and `commands.schema.json` left `agent_notes`, `args` and `subcommands` optional, though all five are non-optional in the source and never absent — that direction costs nothing at parse time and everything in agent code, which then guards against a field that never goes missing. `doctor.schema.json` named check ids `tls` and `cache_dir`, neither of which exists; the twenty real ids are now listed, along with the note that TLS posture is reported by `http_client_posture`.
- **A wire field existed that no document taught (GAP-DOC-FIELD-001):** `commands --json` emits `data.agent_notes.json_auto`, declared in its schema, and no prose document in the repository named it. Measured across the twenty schemas: 128 distinct field names, exactly one with no document behind it — and it is the field that states when JSON is chosen without being asked for, which is policy rather than detail. The existing documentation gates derive from commands, flags, kinds and schema *names*; field is a fourth vocabulary and had no gate. New `no_schema_field_goes_untaught` requires every declared field to appear in some prose document, and its canary proves the extraction reaches nested blocks, since `json_auto` sits two levels down inside `agent_notes`.
- **Decision records contradicted the manifest and pointed at files that had become directories (GAP-ADR-STALE-001):** ADR 0007 section 1 said the rustls pin carried **no crypto feature** while `Cargo.toml` enables `ring`, and section 2 of the same document says the provider *is* `ring` — a document that disagrees with itself passes any gate that reads one half. ADR 0002 promised `ErrorKind` and `AppError` agree on retryability, which the `io` kind breaks by design, and both 0002 and 0001 described exit 74 as two kinds when it carries three. ADR 0003 pointed at `src/crates_io.rs` and `src/retry.rs`, ADR 0004 at four more; all six are directories now, and four of them sat in a list of five, so the `Related` section — the pointer an auditor follows to check a decision against the code — cost exactly the reader doing the right thing. New ADR 0010 records Explicit Target Designation, which had refused two verbs with exit 64 since 2026-08-10 with no architectural record at all, and new `no_decision_record_points_at_a_source_path_that_is_gone` scans every record for `src/` citations in both spellings.
- **The configuration reference gave the exit code of the wrong layer (GAP-DOC-EXIT-001):** it said a zero timeout fails with exit 65 and that a value above a hard max fails with exit 65, both true on the flag and both false in `config.toml`, where the same values exit 78 with `kind=config`. The file failure lands at load, so an inherited `timeout_secs = 0` breaks every command rather than the one being run, and `MIGRATION` never announced that break at all. The same page claimed there is no silent clamp while seven knobs are clamped in silence, including `connect_timeout_secs` being lowered to `timeout_secs`, omitted the defaults of seven knobs, and named `max_redirects` as the only key without a flag when there are five.
- **The three `llms` bundles taught none of the eight reduction flags (GAP-DOC-LLMS-001):** measured at zero of eight in `llms.txt`, `llms.pt-BR.txt` and `llms-full.txt`, and two of eight in `INTEGRATIONS.md` and its pair. `llms-full.txt` taught ten flags, all transport, and no reduction at all. The cause sits in one file: `CONTRACT_DOCS` listed ten documents and omitted these five, while `CATALOG_DOCS` — twenty lines below, in the same module — listed all five for the command surface. Two sibling constants answering different questions about the same files, never compared, so the undefended half drifted. The `llms` bundles are the worst place for this, because they exist so an agent can learn the surface without reading the tree: a flag missing there does not exist for the reader they were written for. All five gained a reduction section and joined `CONTRACT_DOCS`, which went from ten entries to fifteen; the flag list stays derived from `AgentArgs`.
- **Rustdoc credited the line ceiling to a script deleted weeks earlier (GAP-DOC-SCRIPT-001):** `src/agent_ops/tests.rs:4` said the 500-line ceiling was "enforced by `scripts/check-policy.sh`" in a `//!` block that ships as published documentation. The ceiling is real; the enforcer named is `no_source_file_exceeds_the_line_ceiling`. No gate could catch it — script gates read `scripts/`, prose gates read `.md`, and nothing compared a *mention* of a path against the filesystem. New `no_file_names_a_gate_script_that_does_not_exist` derives the existing scripts from the directory and scans source, tests, scripts and current documents, exempting past-tense lines so the five legitimate historical references survive. Its canary assembles the path from two literals: written contiguously it would be a dangling reference inside the very gate that rejects them, and exempting the gate's own source would be a hole, which is worse than the defect.
- **A gap's `### Estado` asserted counters that describe the host (GAP-TARGET-TOOLING-001):** GAP-APPLE-CAUSE-001 recorded `checked=4 skipped=2 cross_checked=2`, and the same host produced `checked=2 skipped=4 cross_checked=1` the next day with nothing regressed in this crate — `zig` had left the machine, and `cargo-zigbuild` alone builds nothing. Those counters were never a property of the repository; they describe which toolchains happened to be installed. Both cross-platform matrices gained a section naming the five host tools and what each one drives, and new `the_support_matrix_names_every_host_tool_the_cross_gate_requires` derives the target-to-tool pairs from `cross_tools_for()` inside the script itself. It caught `oa64-clang`, the Apple probe, missing from both matrices on its first run. Same class as GAP-TRACE-001, and the same remedy: stop writing the number, derive the thing the number stood for.
- **The configuration reference had no gate, and was missing two flags (GAP-DOC-CONFIG-001, closure):** the gap closed its documentation half and left the gate open in its own `### Estado`. New `every_global_flag_appears_in_the_configuration_reference` derives the fields from `src/cli/mod.rs` by pairing `#[arg(… global = true …)]` with the `pub` field beneath it, converting underscores to hyphens. On its first run it reported four problems: `--verbose` and `--quiet` were taught only as `-v` and `-q`, so the long forms existed for `--help` readers and not for reference readers. The sibling surface now has the same defence `AgentArgs` always had.
- **No gate could tell a true historical note from a corrupted one (GAP-DOC-HISTORY-001, closure):** the count gate compares every claim against `docs/schemas/` on disk, and the disk only knows today, so a note about 1.2.0 was unfalsifiable by construction. New `no_two_documents_disagree_about_the_same_release` resolves the release heading governing each schema count, groups by release, and fails when one release receives two different counts. It needs no oracle: what a past release contained survives in the agreement between the documents describing it, and disagreement is the signal. It scans the historical set too, because the comparison is between peers rather than against the tree.
- **The changelog announced 1.2.1 as the next release while 1.3.0 sat above it (GAP-DOC-CHANGELOG-ORDER-001):** both changelogs carried `## [Unreleased] (1.2.1, unreleased)` *below* `## [1.3.0]` and *above* the released `## [1.2.1] — 2026-08-08`, so a reader met two 1.2.1 blocks and concluded the pending release was 1.2.1. ### Changed
- **`ring` stays, and the reason is now measured rather than argued (GAP-TOOLCHAIN-001):** the product rule says this CLI is self-contained and Rust-native, yet `ring` compiles `crypto/*.c` through `cc-rs` — `cc v1.3.0` enters by `ring → rustls-webpki → rustls-platform-verifier → reqwest`. Both pure-Rust replacements were swapped in and measured. `graviola` removed the C completely: `cargo tree -i cc` printed nothing and all four non-Linux targets cross-checked clean with no compiler installed, type-checking `#[cfg(windows)]` for the first time. It was rejected because it requires the x86_64 `adx` feature (Broadwell, 2015+): on a Haswell host it compiled, passed all 441 offline tests, and aborted the process at the first live handshake — nothing in the suite touches the network, so nothing could have caught it. `rustls-rustcrypto` has no CPU floor and also removed the C, but pins `rustls-webpki ^0.102`, which carries RUSTSEC-2026-0049/0098/0099/0104 (name constraints wrongly accepted, CRLs not authoritative, reachable panic in CRL parsing) plus `rsa` 0.9.10 with RUSTSEC-2023-0071, for which no patched version exists. Trading a build-time dependency for weakened certificate validation is not a trade a TLS client may make. The non-conformance is therefore recorded with its measured cost and two objective reopen criteria: a non-`adx` fallback in graviola, or a patched webpki in rustls-rustcrypto.
- **Dedup borrows instead of cloning (GAP-ALLOC-001):** `finalize_hits` cloned every candidate name into a `HashSet<(String, ItemKind)>` because the same `String` was needed by both the set and the hit it moved into. Splitting the decision from the construction removes that conflict: the first pass borrows `&str` from the rows, the second consumes them, and capacity is now the measured survivor count instead of `limit.min(rows.len())`. Result and order are unchanged. Measured on `tokio` (285 hits, warm cache) the command holds at 23 ms, so this is an allocation win, not a latency one — which is what the original rejection of this gap said, and remains true.
- **Sequential anchor probing reconfirmed with its mechanism (GAP-PROBE-001):** the rejection cited a 12.6x regression without naming the cause, which is why it kept being reopened. The cause is the politeness delay: `rate_limit_delay_ms` defaults to 1000 and is keyed by host, while all five entries of `parent_kind_probe` resolve against that same host. Measured: `Duration::MAX`, which hits on its first probe, completes in 104 ms; `Iterator::Item`, which needs a second request, takes 1083 ms. The extra second is the throttle, not the network — so the floor for N probes is (N-1) × delay whether they are issued serially or concurrently, and a fan-out would only add coordination on top.

Both ADRs now state that `ring` is accepted with the non-conformance recorded, that `graviola` and `rustls-rustcrypto` were rejected on measurement for opposite reasons, and that `cargo tree -i ring` and `-i cc` **do** print. Gate E derives the live provider from `src/main.rs` and rejects any document that accepts a different one or shows a different one being installed.
- **The cross-target gate probed for a file that cannot exist (GAP-GATE-003):** `check-targets.sh` asked `command -v lib.exe` before checking `x86_64-pc-windows-msvc`. `lib.exe` is Microsoft's archiver and cannot exist on Linux, so the condition was unsatisfiable and msvc was skipped on every run that would ever happen — leaving `cross_checked=0`, a permanent exit 1, and a pendency that read as the maintainer's decision across three audits. `cargo-xwin`, `clang-cl` and `llvm-lib` were already installed on the host the whole time, and the gate's own hint named `cargo-xwin` three functions below the probe that ignored it. The probe now asks for the tools the remedy actually uses and routes msvc through `cargo xwin check`. Measured: `checked=2 skipped=3 failed=0 cross_checked=1`, exit 0 — so `#[cfg(windows)]` in `src/shutdown/signals.rs` is type-checked on this host for the first time. `x86_64-pc-windows-gnu` still needs `mingw64-gcc` and both Apple targets still need an SDK zig does not ship, so those three stay honestly skipped. The measured cost recorded under GAP-TOOLCHAIN-001 — "no non-Linux target is verifiable on this host" — was a generalisation from two failures of a probe rigged to fail, and is corrected in place.

### Added
- **`--sort-by` and `--max-items` complete the agent-native pipeline (GAP-AGENT-001):** the reduction surface shipped six of the eight operations an agent-first CLI owes its caller — it could filter, project, deduplicate, count, truncate strings and cap bytes, but it could neither order nor limit. Measured live, `--filter kind=struct` cut `search-in-crate serde ""` from 62 hits to 32, and there was no way to ask for five of those 32 without piping stdout through `jaq` — the exact outcome the agent-native rule calls a failure. `search-in-crate --limit` could not stand in, because it bounds the *query* and runs before the filter; `search-crates --sort` could not either, because it orders *upstream* at crates.io. The two flags are one fix rather than two: limiting without ordering returns an arbitrary slice of the matches, which is a worse answer than the full set. `--sort-by` is stable and ascending, compares numbers numerically so `9` precedes `10`, puts elements lacking the key last (unknown is not smallest), and is a no-op — never an error — on a key nobody carries. `--max-items 0` is an empty array with `ok: true`. The names avoid `--limit` and `--sort` deliberately: those already belong to subcommands, and a global duplicate makes clap panic with "Long option names must be unique for each argument", so the collision was designed out rather than worked around. The fixed order is now filter → sort-by → dedupe-by → max-items → select → count-only → truncate-content → max-output-bytes: sorting before deduplication decides *which* duplicate survives, limiting after it stops a duplicate from consuming a slot, and `--count-only` therefore counts the slice. `agent_surface` gained `limited`, which separates a genuinely small result from a truncated one — without it, a caller cannot tell whether raising the cap would return anything more.
- **`agent-surface` schema:** the reduction report was the only payload in the product without a published contract, so agents discovered its shape by trial — precisely what the schema bundle exists to prevent. `docsrs-cli schema --cmd agent-surface --json` now returns it, and `schema --cmd all` carries twenty wire names instead of nineteen.
- **Enum variants and struct fields are reachable (GAP-ASSOCITEM-002):** `get-item std variant option::Option::Some` and `get-item std structfield ops::Range::start` now resolve to `enum.Option.html#variant.Some` and `struct.Range.html#structfield.start`. The rustdoc anchor family had been modelled with three members and has five; `variant.` and `structfield.` were the two never implemented, and one test even asserted `assoc_from_fragment("variant.Some") == None`, making the suite the guardian of the missing support. Neither kind owns a page of its own, so `ItemKind::file_prefix` now returns `Option` — the compiler forces every URL builder to handle that instead of silently emitting `variant.Some.html`, a path no rustdoc has ever served. An unqualified `variant Some` exits 65 naming the parent kinds that can host it. Variant probing tries `enum` alone, because any other parent would spend a GET against a rate-limited origin on a page that cannot carry the anchor.
- **`log_directive` config key:** stderr verbosity is now steerable from `config.toml` (`log_directive = "docsrs_cli=debug,docsrs_cli::http=trace"`), with `-q` / `-v` outranking it and `DEFAULT_LOG_DIRECTIVE` (`error`) as the floor. `config show --json` exposes it, so an agent can read the effective value. An unparseable value is rejected at load time (exit 78) — see GAP-TOML-002 below for why the original silent fallback was the wrong shape.
- **Environment-read gate:** `scripts/check-policy.sh` fails on any `env::var` / `option_env!` / `from_default_env` in `src/` outside an exhaustive allowlist of three terminal-capability variables plus `CARGO_PKG_*`. `from_default_env` is matched by name because it reads the environment without ever naming the variable, so a string allowlist alone would never catch it. A second check confines `sys_locale` to `src/i18n/`, because a dependency reading the environment inside its own crate is invisible to any scan of our source (GAP-I18N-003).
- **File-size gate (GAP-SIZE-001):** `scripts/check-policy.sh` now fails when any file under `src/` or `tests/` exceeds `MAX_FILE_LINES` (500), naming each offender with its measured count. The 1.2.1 plan required this ceiling but nothing enforced it, so it regressed in silence during that very release — `src/config/load.rs` went from 499 to 537 lines. The metric is `tokei`, which counts **neither** `///` nor `//!` lines in any bucket; documenting an item must never push its file over the limit in a crate that enforces `#![warn(missing_docs)]`. A host without `tokei` skips the check with a stderr notice instead of passing quietly.

### Changed
- **`emitted` counted what was not emitted (GAP-COUNT-001):** `SearchInCrateData::emitted` is documented as "hits actually emitted" and the schema marks it required, so agents are taught to trust it — yet after `--filter kind=struct` it reported 62 beside 32 hits. The reduction layer rewrote the array and left the sibling that describes that array untouched, so an agent paginating on `emitted` was wrong by thirty elements. It is the same class as GAP-TOML-001: two places in one envelope answering the same question with different numbers. `EMITTED_COUNT_KEYS` now sits beside `RESULT_ARRAY_KEYS` and holds exactly `emitted`, rewritten after every shrink including the one `--max-output-bytes` forces. The tempting generic rule — rewrite any integer sibling equal to the pre-reduction length — was measured and rejected: in that same envelope `total` also held 62, and `total` counts what the upstream index classified, making it the one number that survives a filter intact. Redefining `emitted` in the docs as "before reduction" was rejected too, because a field named `emitted` that does not count the emitted rows is misleading by construction.
- **Single-responsibility split, fifth pass (GAP-SIZE-002):** four files sat within 25 lines of the 500-line ceiling — `src/ops/get_item.rs` (495), `src/agent_ops/mod.rs` (487), `src/cli/mod.rs` (481), `src/cache/disk.rs` (477) — and the two new flags would have pushed two of them over. Splitting after the change would have left the repository failing its own gate at an intermediate commit, which is how a ceiling starts teaching people to split by size instead of by responsibility, so the splits landed first. `src/cli/agent_args.rs` holds the reduction flags as a flattened `AgentArgs`: declaring how much of the payload reaches the caller is a different job from declaring how the request is made, and it also removed a growing positional argument list from `AgentOps`. `src/agent_ops/tests.rs` follows the precedent of `src/cli/tests.rs` and `src/error/tests.rs`. `src/ops/get_item.rs` became `src/ops/get_item/` with `mod` (parse, fetch, emit) and `recover` (the not-found ladder) — fetching an item is one GET, while recovery is a catalog round trip, a parent-page probe and two resolution shapes, and it is the half that grows with every rustdoc anchor family. The largest file is now `src/cache/disk.rs` at 477 lines, recorded in `gaps.md` as the next candidate.
- **The flag rejected what `config.toml` accepted (GAP-TOML-001):** `--timeout 0` exited 65 with `timeout must be >= 1 second (got 0)`, while `timeout_secs = 0` in `config.toml` was accepted — and `config show --json` then reported `"timeout_secs": 0` as though it were in force. One knob, one value, two opposite answers depending on which layer supplied it. The validation lived in `src/cli/overrides.rs`, the file that owns the flags, so `apply_toml` only copied the value across; of its thirteen numeric keys it validated exactly two, and both already used `ValueSource::ConfigFile` six lines below the unguarded assignment. The type existed to model precisely this divergence and the call site simply had not applied it. Both timeouts now fail closed from TOML with exit 78 (`config`) while the flags keep exit 65 (`invalid_input`): one rule, two remedies, because the operator edits a file and the caller edits a command. `retry_max_elapsed_ms = 0` and `max_cache_bytes = 0` are untouched — there zero has a documented meaning (derive from `--timeout`; unlimited) rather than being a violation. What let this survive is that every test exercised one layer at a time, and a per-layer test can never reveal a disagreement *between* layers.
- **An unparseable `log_directive` was swallowed (GAP-TOML-002):** `log_directive = "!!!garbage!!!"` produced exit 0 and no logging, leaving the operator with a key that does nothing and no way to find out why — the same shape as the ambient override this key had just replaced. The silent fallback was deliberate and its rustdoc gave the reason: a typo in an optional diagnostics knob must not take the command down. The reason is sound; the placement was not. `init_tracing` runs before any structured error path exists, so swallowing was its only option — but `EnvFilter::try_new` is pure and cheap, so the check moved to `apply_toml`, where `AppResult` is already in hand and the failure joins every other bad TOML value at exit 78. `Subject::LogDirective` entered the vocabulary and the exhaustive renderers forced both sentences to be written. The fallback stays as defence in depth, now unreachable from the TOML path.
- **The rustdoc denied an environment read that happens (GAP-I18N-003):** `src/i18n/mod.rs` stated "Product never reads locale from environment variables", which two commands disprove: `LANG=pt_BR.UTF-8` yields `erro: tipo de item desconhecido 'widget'` and `LANG=C` yields `error: unknown item type 'widget'`. `sys_locale::get_locale` consults `LC_ALL` / `LC_MESSAGES` / `LANG` on Unix. The policy gate could not catch it because it scans `env::var` in *our* source and the read happens inside the dependency — a green run was proof of no *direct* read, never of no read. The behaviour itself is correct and stays: host-locale detection is universal CLI convention, it belongs to the same category as `NO_COLOR` and `TERM`, `--lang` and the TOML `lang` always outrank it, and the same A/B shows the JSON `message` staying English under either value. The defect was the claim. The rustdoc now states the read and its category, and the gate enforces *confinement* — `sys_locale` may appear only under `src/i18n/` — because confining the read is what makes the claim auditable, whereas denying it only made it invisible.
- **`RUST_LOG` was a product knob that outranked the CLI (GAP-ENV-001):** `RUST_LOG=trace docsrs-cli version -q` emitted log lines against the `-q` the caller typed, and no `docsrs-cli` command could turn them off — while `doctor` reported `(no env)` in its payload. The module's own rustdoc admitted the behaviour in writing: "When `RUST_LOG` is set, it wins over CLI verbosity". The practical harm is not the rule violation; it is that an ambient value made the product unconfigurable *by the product*, breaking the agent-first promise of controllable diagnostics. `EnvFilter::try_from_default_env()` is gone; the filter comes from CLI flags, then the XDG `log_directive`, then the default. `NO_COLOR`, `TERM` and `CLICOLOR_FORCE` stay by explicit decision and are now documented as a separate category: they describe the *device*, the way `isatty` does, and never carry product configuration.
- **Error text is a typed catalogue, not a prose matcher (GAP-I18N-002):** localization worked by matching the *English text* of a message with `starts_with` — 32 arms guarding 145 construction sites across 41 files — and its fallback returned the English unchanged. Rewording an English message silently dropped its Portuguese translation, and a brand-new message was indistinguishable from a translated one; no test could go red, because there was nothing to observe. `ErrorDetail` now carries the *data* of each failure and two exhaustive renderers own the words. Neither `match` has a `_` arm, so adding a variant without writing both sentences is a compile error (`E0004`), verified by removing an arm. `AppError::new` and `AppError::with_source` were removed outright, which makes the untranslated path unrepresentable rather than merely discouraged. The JSON `message` field is byte-for-byte unchanged: English remains the wire contract, and `AppError::localized` is the only path to Portuguese. Upstream text from `reqwest`, `std::io`, `serde`, `toml` and `clap` is carried verbatim with only the *operation* translated — inventing a Portuguese version of someone else's sentence would be worse than leaving it be. Deriving the kind from the detail surfaced two real divergences the prose matcher had hidden: an invalid origin must stay `config` (exit 78) rather than becoming `invalid_input` (65), and the same over-limit value carries a different kind depending on whether it came from a flag or from `config.toml`. Live verification surfaced a third: Portuguese adjectives agree with their noun, so the first rendering produced "consulta de busca está vazio" — a defect class a table keyed on English prose can never expose, since English has no agreement.
- **Path normalization had three copies and kind names had four (GAP-DRY-001):** `strip_crate_prefix_segments` was reimplemented inline in both `src/docs_rs/urls.rs` and `src/docs_rs/fetch.rs`, the latter carrying the comment "the same way URL builder does" — a promise the compiler could not keep, and the exact shape of GAP-ASSOCITEM-001, where detection and URL construction read different rules. Separately, three `*_PARENT_KIND_NAMES` arrays mirrored three `ItemKind` arrays by hand, directly beneath a rustdoc promising "single source of truth", and a fourth copy sat in `urls.rs`. Reordering the kinds without reordering the strings would have made `--dry-run` publish a probe order the live fetch never walks, to an agent that plans on exactly that field. The names are now derived from the kind list and all four arrays are gone. The test that compared the two tables became a tautology once drift was unrepresentable, so it was retargeted at what remains checkable: the wire spelling of every probed kind, in probe order, with nothing dropped.
- **Named constants for magic values (GAP-CONST-001):** `HTTPS_PORT`, `CONFIG_FILE_NAME`, `PLACEHOLDER_CONTACT_HOST` and `DEFAULT_LOG_DIRECTIVE` joined `src/config/constants.rs`; `MAX_BACKOFF_SHIFT`, `MIN_DERIVED_ELAPSED_MS`, `MILLIS_PER_SECOND`, `SHA256_HEX_LEN`, `RATE_LIMIT_DIR_NAME` and the four `--suggest` ranking bands stayed in the modules that own them. The split is deliberate: product configuration belongs in `constants.rs`, arithmetic invariants belong next to the arithmetic. `SHA256_HEX_LEN` derives from `SHA256_DIGEST_BYTES * 2` so the constant states why 64 is 64. `doctor` had duplicated the repository URL twice against a rustdoc reading "never duplicate the GitHub URL as a string literal", and `"config.toml"` was joined onto the config directory in four separate modules.
- **Single-responsibility split, fourth pass:** the new catalogue would have pushed `src/error.rs` (485) well past the ceiling, so it was split before it grew: `src/error/` with `mod` (the `AppError` shape and exit-code mapping) · `vocab` (the stable dictionary of subjects and operations) · `detail` (the catalogue, which grows with every new failure) · `render/en` · `render/pt_br` (one file per language) · `tests`. The two renderers live apart because each language catalogue grows on its own schedule.
- **The file-size gate measured a proxy, not the ceiling it named (GAP-GATE-002):** it declared `MAX_FILE_LINES=500` and returned 0 while three files sat above it — `src/cli/mod.rs` at 586 real lines (458 reported), `src/lib.rs` at 578 (480), `src/shutdown.rs` at 531 (423). `tokei` reclassifies `///` and `//!` blocks as embedded Markdown and reports them on a separate language row, so reading only the Rust row measured each file with its rustdoc deleted. Excluding rustdoc was deliberate — "documenting an item must never push its file over the limit" — but the effect was an inverted incentive: the better a file was documented, the more of it went missing, and `src/error.rs` hid 113 lines. The metric is now physical lines, counted the way an editor counts them. A file that only exceeds the ceiling because of rustdoc is still a file that does too much; the answer is to split it, never to hide the lines. This reverses the metric decision recorded under GAP-SIZE-001, which closed the "no gate" hole but left the measurement one open.
- **Single-responsibility split, third pass:** the corrected gate named four files, each split along a seam already present in the code. `src/i18n.rs` (528) became `src/i18n/` with `mod` · `translate` · `tests`, because rendering English error prose into Portuguese is a different concern from deciding *which* locale is active — and it is the half that grows with every new error kind. `src/lib.rs` (578) handed `execute` and `dispatch` to `src/dispatch.rs`, leaving the crate façade with module declarations and the `run` / `run_with_io` entry points; both functions stay crate-private, so no API moved. `src/shutdown.rs` (531) became `src/shutdown/` with `mod` · `signals` · `tests`: deciding *that* work should stop is portable state machinery, while learning the OS asked for it carries every `cfg(unix)` / `cfg(windows)` branch in the crate. `src/cli/mod.rs` (586) handed its test block to `src/cli/tests.rs`. No public signature changed and no file in `src/` or `tests/` now exceeds 500 physical lines.
- **Single-responsibility split, second pass:** `src/agent_ops/mod.rs` (487 lines, 13 under the gate) handed its envelope transformations to `src/agent_ops/reduce.rs`. The module now owns the plan and the order it is applied in; `reduce` owns `locate_array_key` · `array_mut` · `dedupe` · `project` · `truncate_strings` with their own focused tests. A change to flag parsing can no longer silently alter how a payload is rewritten. `src/ops/get_item.rs` also stopped keeping a private copy of the parent-kind probe order: `AssocAnchorKind::parent_kind_probe` is now the single source both the live probe and the suggestion probe read, because two lists that must agree but can drift is exactly how a kind goes missing in one path while staying reachable in the other.
- **`--suggest` help text matched a behaviour it never had:** it promised "one extra request" and listed the ranking modes as if the flag enabled them. Recovery already ranks nearby symbols without the flag; the flag only guarantees the suggestion field is present, so an agent can tell "no candidates" from "not attempted". The text now says that.
- **Single-responsibility split (D-18):** four oversized files were split along the boundaries already present in the code, never by line count. `src/retry.rs` (524) became `src/retry/` with `config` · `classify` · `backoff` · `tests`. `src/docs_rs/html.rs` (532) became `src/docs_rs/html/` with `version` · `sanitize` · `extract` · `tests`, each CSS selector and scrub regex moving into the submodule that uses it. `src/config/load.rs` (537) became `src/config/load/` with `template` · `toml_file` · `init` · `paths`. `src/http/client.rs` (515) handed its per-host throttle to `src/http/rate_limit.rs`, which already owned the matching stamp and lock I/O. No public signature changed; the largest file in the repository is now 458 lines.

### Fixed
- **Suggestions degraded when the parent's name was ambiguous (GAP-SUGGEST-003):** found during live verification of the new kinds, not predicted by the plan, and pre-existing — it hit `method` long before this release. `get-item std structfield ops::Range::strt --suggest` answered with five structs named `Range` and zero fields; `method ops::Range::nxt` answered with the same five structs and zero methods. An anchor miss means the parent page *was* found and only the member was absent, so re-resolving the parent through `all.html` had nothing to discover — and actively hurt, because an ambiguous leaf makes `pick_unique_type_path` give up and the fallback then suggests the same-named types. The recovery path now goes straight to the parent's anchors on an anchor miss, falling back to the catalog only when the member list comes back empty, where a reexport can still be reachable. It also skips an `all.html` download, which for `std` is substantial. `ops::Range::strt` now answers `ops::Range::start (structfield)`.
- **`GAP-MACOS-001` was documented as open three rounds after it was fixed:** `src/concurrency.rs` has used a runtime `cfg!` guard since the fix landed, and `gaps.md` still pointed at `src/shutdown.rs:251`, a path removed when that file became a directory, and named `extract_method_markdown_scoped_from_document`, which had been renamed. A document that points at code which no longer exists teaches the reader not to trust it. References are reconciled; the cross-target countermeasures stay open and blocked on GAP-TOOLCHAIN-001.
- **A last-resort error path printed English regardless of `--lang`:** `src/lib.rs` wrote `error: {message}` with a hardcoded prefix when a domain error escaped the structured emit path. It is rare enough to have gone unnoticed, and now routes through `Locale::format_error` like every other error, with the locale re-read from argv since `cli` has already been moved.
- **Rustdoc disambiguator suffixes drowned the suggestions (GAP-SUGGEST-002):** found during live verification, not predicted by the plan. `get-item std type iter::Iterator::item --suggest` answered `Item`, `Item-1`, `Item-10`, `Item-100`, `Item-101` — four of five entries unusable. Rustdoc appends `-<n>` when one member name repeats across impl blocks, and the edit-distance ranking *prefers* those suffixed ids precisely because they sit closer to the typo than the canonical name does. A Rust identifier can never contain `-`, so any hyphen in an extracted anchor name is that suffix and nothing else: names are now truncated there and duplicates collapse through a `HashSet` that preserves document order. All three families now answer with exactly one correct suggestion. The offline fixture carried one anchor per name, which is why a green suite never saw this.
- **A redundant predicate rebuilt the defect at the boundary it excluded (GAP-ASSOCLEAF-001):** `get-item std type iter::Iterator::item` built `std/iter/Iterator/type.item.html`, `const time::Duration::max` built `std/time/Duration/constant.max.html`, and `fn runtime::Runtime::New` built `tokio/runtime/Runtime/fn.New.html` — the same impossible shape GAP-ASSOCITEM-001 was supposed to retire, with `--suggest` answering `(none)` in all three. `associated_item_path` was ANDing two predicates where one carries all the information: an uppercase parent (which fires rustc's `non_snake_case` lint if it were a module, so an uppercase parent *is* a type and the path can never be a free item), and the leaf's letter case matching the kind's convention. The second predicate adds no discriminating power once the parent is known to be a type — it only narrows the domain and recreates the original defect inside the range it excludes. It is gone; only the empty-leaf guard remains, because `Parent::` has no member to anchor. `u32::MAX`, `f32::EPSILON` and `io::Result` are untouched: all three depend on the *parent* being lowercase. The three combinations that changed returned impossible URLs, so nothing that worked was lost — a case typo now reaches the parent page and fails with the real member names. The test that asserted the old behaviour described the mechanism rather than the desired outcome, which is how a green suite kept an impossible URL alive; it was replaced with one that names its intent.
- **Two bootstrap messages escaped i18n (GAP-I18N-001):** `src/main.rs` printed a fixed English literal when the rustls `CryptoProvider` was already installed and when the async runtime failed to build, ignoring `--lang pt-BR` — the only two `eprintln!` calls in `src/`. Both fire during bootstrap, before clap parses argv, so `Locale::resolve` and the XDG config are unavailable; reading `config.toml` there would put disk I/O ahead of TLS setup and invert the bootstrap order fixed by ADR 0007. `Locale::from_argv_for_bootstrap` now scans argv for `--lang <tag>` / `--lang=<tag>` in one linear pass — no disk, no environment variable — and feeds `soft_from_tag` rather than `parse_supported`, so a malformed tag cannot turn a bootstrap failure into a second, unrelated error. `scripts/check-policy.sh` gained a check with a deliberately empty allowlist, so the next literal fails the gate instead of shipping English-only.
- **Trait associated items were unreachable (GAP-ASSOCITEM-001):** `get-item std type iter::Iterator::Item` exited 66 while building `std/iter/Iterator/type.Item.html`, a path rustdoc has never emitted in any version. Same for `ops::Deref::Target`, `serde de::Deserializer::Error` and `time::Duration::MAX`, and `--suggest` answered `(none)`, leaving no route at all. Rustdoc has no single "method anchor": it emits **one id prefix per member category**, all coexisting on the parent page — measured live on `trait.Iterator.html` with `htmlq '[id]'`: 198 `associatedtype.` ids, 75 `method.`, 1 `tymethod.`. Fixing `tymethod` in 1.2.1 closed one member category and left its siblings behind, because that fix treated the anchor axis only inside the method path and never revisited which kinds enter it. `src/docs_rs/assoc.rs` now owns the whole family — prefixes, parent-page probe order, and the detection rule — and `is_method_path` is a one-line view of it. The discriminator is the parent segment starting uppercase, which is exactly what keeps `u32::MAX` and `f32::EPSILON` on the legacy module page that std still serves for primitives, both guarded by regression tests. Probe order now leads with the kind that hosts each category (trait for associated types), saving two GETs per lookup against a rate-limited origin, and `--suggest` stopped being blind: it reads anchors off the parent page already in hand, never `all.html`, which lists the trait but none of its members. Suggestions are labelled with the kind the caller typed, so they are copy-paste ready. Enum variants (`variant.`) and struct fields (`structfield.`) would need new CLI kinds and stay out of scope, recorded in `gaps.md`.
- **Required trait methods answered not-found (GAP-TYMETHOD-001):** every body-less trait method — `iter::Iterator::next`, `fmt::Display::fmt`, `de::Deserializer::deserialize_bool` — exited 66 while its provided sibling on the same trait exited 0. Rustdoc emits two anchor id prefixes that coexist on one trait page: `method.NAME` for inherent and defaulted methods, `tymethod.NAME` for required ones (upstream contract, guarded by rustc's `anchor-id-trait-tymethod-28478.rs`). The product only knew `method.`, so the parent page answered HTTP 200 and the anchor lookup failed closed. Resolution had to happen at the anchor level: `all.html` does not list required methods at all. `METHOD_ANCHOR_PREFIXES` now drives a single DOM pass that tries both ids — prefix order decides the winner, never document order — and `source_url` echoes the anchor that actually exists instead of the one the URL builder guessed. `--suggest` sees required methods too, the miss message names both ids tried, and `--dry-run` reports `planned_method_anchors`. The whole test corpus had used one anchor flavour (an inherent struct method) in its only fixture and its only live smoke case, which is why 374 green tests never noticed; a trait fixture carrying both prefixes and two paired live smoke cases close that hole.
- **`--suggest` edit distance was unreachable end-to-end (GAP-SUGGEST-001):** `Runtimee`, `Runtimme` and `Buildr` all answered `(none)` although each is one edit from a symbol in the index. The ranker was correct; the caller was not. Recovery queried `all.html` with the typed leaf under `MatchMode::Prefix`, so a typo filtered the catalog to zero rows and the ranker never received a candidate to score. An empty catalog now widens to the full index through the same already-fetched URL, served from the disk cache rather than a second connection, and a failed widening never masks the original not-found.
- **Cross-target gate passed with zero coverage (GAP-GATE-001):** `scripts/check-targets.sh` exited 0 on a host where the only non-Linux target was skipped, making "skipped" indistinguishable from "verified" — a false green in the very gate written to close the macOS build break. Non-Linux targets are now counted separately and zero coverage fails; `--allow-no-cross` turns the previous silence into an explicit decision. `ring` compiles C in its build script, so cross `cargo check` still needs a C cross-compiler, and the `#[cfg(windows)]` signal wiring in `src/shutdown.rs` remains a declared dead zone.
- **Packaging carried 230 MB of archived backups (GAP-PACKAGE-001):** `cargo package --list` included two multi-hundred-megabyte `.7z` GraphRAG backups and a tool scratch directory, against the 10 MiB crates.io ceiling. - **Single responsibility (D-18 / D-19):** six files exceeded the 500-line limit. `ops.rs`, `meta_cmds.rs`, `render.rs`, `crates_io.rs` and `docs_rs/mod.rs` became directories with cohesive submodules, and the two large integration test files were split by surface. - Still no product env knobs, no telemetry, no CI and no GitHub Actions. Validation stays local.

The build log only ever shows the default target, which is why this stayed hidden. This is the same root cause as the `ring` non-conformance above.
